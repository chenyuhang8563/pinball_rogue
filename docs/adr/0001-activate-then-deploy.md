# 布设系统：先激活关卡，再进入布置阶段

布设系统让玩家在下一场战斗开始前，把持有的桌面组件（木桶、弹力板、传送门）布设到新关卡桌面。我们决定把 `BattleGateway.start` 拆成「激活关卡」与「开始会话」两步，布置面板插在两步之间：玩家选定战斗节点后，关卡先激活（`_activate_level_for` 执行既有校验），树暂停进入布置阶段，玩家直接在新关卡桌面上布设组件（实例化进 `TableBase/TableComponents`），确认后开始战斗会话。BOSS 层同样在奖励确认后走「激活 → 布置 → 开战」。

选「先激活关卡再布置」而非「面板收集布设方案、关卡激活时应用」：前者让布设直接作用于真实关卡——组件即时进场景树、复用关卡校验结果、布置时可见新关卡的敌人与布局；代价是 BattleGateway 契约拆成两步、开战路径需显式管理「激活后、会话前」的中间态。后者保住契约不变，但布设与生效分离、无法在布置时看到真实桌面。

## Considered Options

- **方案应用机制（已放弃）**：布置面板收集「布设方案」（组件场景 + 位置 + 朝向清单），`_activate_level_for` 激活后应用。BattleGateway 契约不动，但布设与生效分离，布置时看不到真实桌面。
- **先激活关卡再布置（采纳）**：如上。玩家布置时所见即所得，布设物直接实例化进活关卡；需要把 `BattleGateway.start` 拆为「激活」与「开始会话」两个可独立调用的步骤。
